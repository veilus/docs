Veilus's [MCP server](/reference/mcp/) lets an LLM agent — Claude Code, Cursor, Claude Desktop, or anything else that speaks MCP — write a real [Playwright](https://playwright.dev) script, run it against one of your profiles, read back what happened, and fix it, without you copying code back and forth by hand.

## Setup

<Steps>

1. **Turn on the local API.** Open the **API & MCP** page in the app sidebar and enable it. It only listens on `127.0.0.1`.

2. **Mint a token.** Name it after the tool that will use it (e.g. `claude-code`) so you can revoke it later without affecting anything else. The value is shown once — copy it.

3. **Connect your LLM tool.** The **API & MCP** page has a ready-made snippet for Claude Code, and a JSON block for Cursor / Claude Desktop. See [MCP Server](/reference/mcp/) for the exact commands.

</Steps>

## Ask it to write a script

Once connected, just describe what you want in your own words, for example:

> Write a Veilus script that opens `https://example.com`, waits for the page to load, and logs the page title. Read the URL from a variable called `TARGET_URL`.

The LLM has the [`save_script`](/reference/mcp/#save_script) tool, whose description carries the exact rules a script must follow — it doesn't need you to repeat them.

## The loop

This is what happens behind the scenes, and what you'll see if you watch the agent work:

1. **`save_script`** — the LLM writes TypeScript and saves it into Veilus Flow. Saving without a `script_id` creates a new script; passing one back in replaces its source.
2. **`run_script`** — runs the script on up to three of your profiles (a script the LLM just wrote isn't approved yet, so it's capped until you approve it — see below). Returns a `run_id` right away, without waiting for the run to finish.
3. **`get_run_result`** — reads back each profile's exit code and the tail of its stdout/stderr.
4. If something's wrong, the LLM reads the error, fixes the script, and calls `save_script` again with the same `script_id`. Repeat until it works.

Variables you mention (like `TARGET_URL` above) become environment variables inside the script, named `process.env.VEILUS_VAR_<NAME>` — the LLM handles this naming for you, but it's useful to know when reading a script it wrote.

## Approving the script

A script an agent saves is **not approved** until you say so. Unapproved scripts can still be run directly through `run_script` (capped at 3 profiles), but they can't be used in schedules or larger batch runs.

To approve one:

1. Open **Veilus Flow** and find the script (agent-authored scripts are marked as such).
2. Read the source. This is a real Node program that will run with your user's permissions — review it the way you'd review any code someone else wrote before you run it.
3. Click **Approve**.

Editing a script — by hand or by asking the agent to save over it again — un-approves it. It needs another look and another **Approve** before it goes back into schedules.

Once approved, use it anywhere a Veilus Flow script is used: on more profiles at once, or on a [schedule](/automation/overview/).

## The script contract

Every script `save_script` accepts must follow the same rules, so it behaves inside Veilus's profile pool instead of launching its own browser. Quoting the tool's own description:

> connect with `chromium.connectOverCDP(\`http://127.0.0.1:${process.env.VEILUS_DEBUG_PORT}\`)`; no `chromium.launch`/`launchPersistentContext`; use `browser.contexts()[0]`, not `newContext()`; no `setUserAgent`/`setViewportSize` — identity belongs to the profile; errors must exit non-zero: `main().catch((e) => { console.error(e); process.exit(1); })`; import only `playwright` and Node built-ins; end `main()` with `await browser.close()` — it only disconnects from the profile's browser and lets the script exit; without it the run hangs.

In short:

- **Connect, don't launch** — `chromium.connectOverCDP` against `VEILUS_DEBUG_PORT`, never `chromium.launch()`.
- **Use the existing context** — `browser.contexts()[0]`. The profile *is* the identity; don't create a new context or override the user agent or viewport.
- **Read input from `process.env.VEILUS_VAR_<NAME>`**, UPPER_SNAKE_CASE.
- **Write output with `console.log`** — that's what the LLM (and `get_run_result`) sees.
- **Exit non-zero on error**, via the `main().catch(...)` pattern below.
- **Always `await browser.close()`** at the end of `main()` — it disconnects, it doesn't close your profile's browser. Skip it and the run hangs until it times out.
- **Only `playwright` and Node built-ins** — no other npm packages.

## A minimal correct script

```typescript
import { chromium } from "playwright";

async function main() {
  const browser = await chromium.connectOverCDP(
    `http://127.0.0.1:${process.env.VEILUS_DEBUG_PORT}`,
  );
  const context = browser.contexts()[0];
  const page = context.pages()[0] ?? (await context.newPage());

  const url = process.env.VEILUS_VAR_TARGET_URL ?? "https://example.com";
  await page.goto(url);
  console.log(`title: ${await page.title()}`);

  await browser.close();
}

main().catch((e) => {
  console.error(e);
  process.exit(1);
});
```

## Security

An agent-written script is a normal Node program that runs with your user's permissions — it can do anything a script you'd write yourself could do. Read what the LLM saved before you approve it, the same way you'd review a pull request.
